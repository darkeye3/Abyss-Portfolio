# 시체 내구도가 생존 HP로 표시되던 오류

죽은 몬스터가 `HP 1/28`로 표시되는 문제를, 규칙 상태를 전달하는 Application 조회 모델과 Unity 화면의 연결에서 해결했다. 시체를 공격해서 제거하는 규칙은 유지하고, 화면에는 **`HP 0/28`과 `시체 내구도 1/1`을 분리해 표시**한다.

## 문제와 원인

몬스터는 사망한 뒤에도 시체로 진형을 점유하며, 공격으로 제거할 수 있다. 이때 Rules의 `CurrentHealth`는 생존 체력이 아니라 **시체를 파괴하는 데 필요한 남은 내구도**를 담는다. 기존 화면이 이 값을 생전 `MaxHealth`와 조합하면서, 사망한 몬스터에게 생존 HP가 남아 있는 것처럼 보였다.

문제는 시체 생성 계산보다 **같은 필드의 상태별 의미가 화면에 전달되지 않은 데** 있었다. 이 프로젝트의 규칙 명세는 시체를 살아 있는 유닛으로 세지 않으면서도 공격으로 파괴할 수 있게 정의한다. 따라서 생존 HP와 시체 내구도는 서로 다른 표시 값이어야 한다.

## 수정의 책임과 판단 근거

| 계층 | 적용한 수정 | 의도 |
|---|---|---|
| Application 조회 모델 | `LivingHealth`, `CorpseHealth`, `CorpseMaxHealth` 제공 | 생존 체력과 시체 내구도의 의미를 명시 |
| Application 조회 조립 | 시체 최대 내구도를 해당 전투의 `battle.Rules.CorpseHealth`에서 전달 | 생전 최대 HP나 UI의 임의 상수로 내구도를 추정하지 않음 |
| Unity 화면 | HP 글자·체력바·툴팁은 `LivingHealth`, 내구도 행은 `CorpseHealth/CorpseMaxHealth` 사용 | 화면 요소들이 같은 의미의 값을 표시 |

설계상 UI의 HP 글자만 0으로 바꾸는 방식은 수정 범위가 작지만, 체력바와 툴팁에서도 같은 분기를 관리해야 한다. 조회 모델에 의미를 분리하면 여러 표시가 공통 기준을 사용한다. 반면 조회 모델에 표시용 속성이 추가되므로, 원시 규칙 값과 표시 값의 용도를 분명히 해야 한다.

Rules의 사망·시체 생성·제거·부패 계산, 난수 소비와 저장 형식은 이 표시 수정에서 변경하지 않았다. `CurrentHealth`를 0으로 덮어쓰면 시체를 공격해 제거하는 데 필요한 내구도까지 사라지므로 원시 상태는 보존한다.

## 기대값을 정한 기준

테스트의 기대값은 화면 구현을 다시 계산해서 만들지 않고, 명시한 상태와 표시 원칙에서 정한다.

| 테스트 입력·상태 | 기대 결과 | 근거 |
|---|---|---|
| 생존 몬스터, 체력 28 / 최대 28 | `HP 28/28`, 체력바 100%, 내구도 행 없음 | 생존 중에는 실제 체력을 표시 |
| 사망한 시체, 원시 내구도 1 / 초기 내구도 1, 생전 최대 HP 28 | `HP 0/28`, 체력바 0%, `시체 내구도 1/1` | 사망 체력과 파괴 가능한 내구도를 구분 |
| 같은 슬롯을 비우고 생존 몬스터로 재사용 | `HP 28/28`, 시체 그림·내구도·사망 표시 제거 | 이전 바인딩의 시각 상태가 다음 유닛에 남지 않음 |
| 죽음의 문 상태인 영웅, HP 0 | 살아 있는 상태 유지, 시체 내구도 0 | **HP 0만으로 사망·시체 여부를 판단하지 않음** |

마지막 조건은 조회 모델의 원본 회귀 테스트에서 확인한다. Unity 슬롯 테스트에는 입력을 만드는 `Unit` 도우미도 함께 공개해, HP 28·내구도 1이라는 값이 어디서 주어지는지 확인할 수 있게 했다.

## 코드와 테스트 읽는 순서

1. [CorpseDisplayState.cs](../excerpts/application/CorpseDisplayState.cs): 상태별 표시 속성과 규칙에서 조회 모델을 조립하는 실제 메서드.
2. [CorpseDisplayView.cs](../excerpts/unity/CorpseDisplayView.cs): HP·내구도·툴팁·그림을 갱신하는 실제 메서드.
3. [CorpseDisplayTests.cs](../excerpts/unity/CorpseDisplayTests.cs): 1칸·2칸 몬스터의 생존 → 시체 → 슬롯 재사용과 저장된 프리팹을 다시 불러온 상태를 검사하는 실제 회귀 테스트.

선별한 메서드 본문과 속성 선언은 원본을 유지했다. 주변 타입·직렬화 필드·공통 테스트 도우미는 생략했으며, `excerpts/`는 저장소의 독립 실행 프로젝트에서 제외한 코드 검토용 발췌다.

## AI 결과를 검증하는 근거

AI를 활용해 작성한 구현·테스트도 **규칙 명세 → 고정 입력의 기대값 → 조회 결과 → Unity 표시 결과**로 대조한다. 이 사례에서는 모델이 제시한 설명이나 전체 assertion 수보다, 사망 HP가 0이면서 시체 내구도 1은 보존되는지와 슬롯 재사용 시 이전 표시가 없어지는지를 근거로 삼는다. 작성 도구가 동일하더라도 기대값의 근거는 구현 코드와 분리한다.

원본 프로젝트의 `CorpseSprite-Unity.xml` 실행 기록에서 당시 실행한 Unity EditMode 테스트 묶음은 **65/65**가 통과했다. 이 중 공개한 슬롯 회귀 테스트는 크기 1·2의 **2개 사례**이며, 화면 렌더 검사는 1280×720·1920×1080의 **2개 사례**다. 렌더 검사는 HP·내구도 텍스트와 화면 범위를 확인하고, 시체 그림을 숨긴 프레임과의 픽셀 차이도 비교한다. 이 수치는 공개 저장소의 독립 실행 테스트 수에 합산하지 않는다.
