# 실행과 테스트

## 실행 방법

필요 환경은 .NET SDK 10.0입니다. Unity나 외부 NuGet 패키지는 필요하지 않습니다.

저장소 루트에서 실행합니다.

```bash
dotnet run --project Abyss.Portfolio.csproj -c Release
```

공개 샘플 검증 결과: **테스트 20개 통과, 실패 0개, 검증식(assertion) 4,527개 통과**. 한 테스트 안에서 여러 입력과 상태를 비교하므로 테스트 개수와 검증식 개수는 다릅니다.

## 전투 효과 통합 테스트

[CombatEffectTests.cs](../tests/CombatEffectTests.cs)

- 명중 판정 이후 지속 피해·시간제 상태·치료 효과가 단계와 목록 순서에 따라 적용되고, 상태 변경과 종류별 C# 타입으로 구분한 결과 이벤트가 일치하는지 확인합니다.
- 빗나간 공격의 명중 후 효과는 건너뛰고, 대상 판정 이후 효과는 실행합니다.
- 치료는 지정한 종류의 스택만 제거하며, 같은 치료를 반복해도 불필요한 사건을 만들지 않습니다.
- 지속 피해 스택의 개별 수명과 소유자 턴 경과를 확인합니다.
- 여러 대상의 처리가 끝난 뒤 스킬 종료 단계가 한 번 실행되는지 검사합니다.
- 추가 난수 판정이 없는 효과가 기본 판정의 난수 상태에 영향을 주지 않는지 비교합니다.
- 잘못된 대상 목록과 효과 정의를 거절합니다.

이 테스트는 원본에서 선별한 세 효과와 상태 컨테이너를 축소된 전투 모델에 연결해 실행합니다.
원본 구현과 샘플용 모델의 구분은 [전투 효과 문서](combat-effects.md)를 참고해 주세요.

## 난수 테스트

[RandomnessTests.cs](../tests/RandomnessTests.cs)

- 전투·전리품 등 용도별로 분리한 난수 수열인 **난수 스트림**을 검증합니다. 전리품 난수를 500회 추가 생성해도 전투·던전 난수의 수열이 유지됩니다.
- 같은 초기값(시드)은 7개 스트림 모두에서 같은 수열을 만듭니다.
- 서로 다른 지점까지 소비한 모든 스트림을 저장·복원한 뒤 다음 수열을 비교합니다.
- 단일 난수원의 저장된 내부 상태(스냅샷)를 복원한 뒤 같은 수열을 만드는지 검증합니다.
- 정의되지 않은 스트림 이름과 잘못된 정수 범위를 거절합니다.

## 그래프 테스트

[GraphSearchTests.cs](../tests/GraphSearchTests.cs)

- 순환이 있는 그래프에서 중복 방문 없이 최단 거리를 계산합니다.
- 연결되지 않은 방과 고립된 시작점의 결과를 확인합니다.
- 시작점 또는 간선 도착 방이 없는 입력을 거절합니다.
- 최장 거리가 같은 방은 입력 순서와 관계없이 ID의 문자 코드 순서(`StringComparison.Ordinal`)로 선택합니다.

## 원본 프로젝트의 검증과 관계

[HeroConfigurationTests.cs](../excerpts/application/HeroConfigurationTests.cs)에는 실제 영웅 설정·저장 실패 회귀 테스트를 발췌했습니다.
선택 목록의 저장 왕복, 잘못된 선택 거절, 저장 오류 후 장신구 슬롯·보관함·선택 상태 복원을 확인하는 코드입니다.
원본 게임의 세션과 콘텐츠를 사용하는 발췌이므로 위 독립 실행 결과에 포함하지 않습니다.

[CorpseDisplayTests.cs](../excerpts/unity/CorpseDisplayTests.cs)는 시체의 HP·내구도 표시와 같은 UI 슬롯의 생존 → 시체 → 생존 전환을 검사하는 Unity 테스트 발췌입니다. [버그 분석 문서](corpse-display.md)에서 기대값의 근거와 실제 수정 코드를 함께 확인할 수 있습니다. 이 발췌도 위 독립 실행 결과에는 포함하지 않습니다.

이 저장소의 테스트 수치는 위 독립 샘플만의 결과입니다. PDF에 소개한 검증식 83,449개는
Unity 없이 실행하는 Abyss 원본 C# 코드(Core)의 규칙·콘텐츠·저장·게임 진행 조정 전체 검증 결과입니다.

원본 프로젝트에서는 코드 작성·리팩터링에 Codex를 활용했습니다. 각 테스트를 규칙 문서의 항목 번호와 연결하고,
허용된 어셈블리 참조 목록 검사, 같은 초기값으로 실행한 결과 비교, 저장 데이터와 기준으로 고정해 둔 전투 사건 순서 비교로 변경 결과를 검증했습니다.
